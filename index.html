一、判決

同類 bot 喺工程上可行。 公開 API、官方 SDK、CTF merge、WebSocket 盤口全部齊。真正難嘅唔係「寫得出」，而係「寫完之後仲有冇邊緣」。

對賬結論有三條硬事實：

  1. 文中公開錢包 l5Zn1bWoM8eTsK 嘅終身盈虧 $66,670 屬實（官方 leaderboard，2026-08-24）。
  2. 文中「每週 $12k」而家唔成立：同一錢包本週 PnL 只有 $347，成交 $11 萬；本月 $18.8k / $617 萬成交。
  3. 文中用 0.55+0.42 做例子，如果兩邊都做 taker，3 仙缺口會被費用食到變負。公開成交顯示佢哋真正喺掃接近已定勝負嘅尾盤，而唔係中間價純套利。

二、原文實際講咩

你俾嘅連結唔係普通推文，而係一篇 X Article，標題係：

I rebuilt my arbitrage bot with Grok Bot and now it makes $12k per week (full guide + code)

發布時間 2026-08-23 16:35 UTC。核心主張：

  • 二元市場 Up + Down 理應等於 $1；低過 $1 就係「無方向風險」嘅定價錯誤。
  • 分兩種：同一市場互補套利，同埋關聯市場組合套利。
  • 用「多智能體」拆開：獵人、風控、費用、執行、對回測嘅對抗審查。
  • 兩邊成交之後用 CTF merge 即刻換返 $1 抵押，加快資金週轉。
  • GTC 掛單賺 maker rebate，FAK 食價要付 taker fee。
  • 最後導去 Telegram 頻道。

同一帳號近日另一條主線（唔係呢篇文，但構成同一套「說話」）係：Polymarket CLOB 有大約 20ms 處理牆，所以 Rust 對 Python 嘅微秒戰爭無意義；活得落嘅策略要喺「幾秒」而唔係「幾毫秒」窗口。另一條係「唔好起 5 分鐘 BTC 預測 bot」，因為機器學習喺呢個窗口接近拋硬幣。

呢個帳號同時賣「免費完整指南」同 Telegram。公開代碼片段係教學級 Python，唔係生產系統。研究只信鏈上同官方 API，唔信標題。

四、策略解剖：邊啲可行

策略窗口可行性備註
尾盤互補掃貨（0.97+0.01 類） 秒至分鐘 高（工程）／中（利潤） 費用接近 0；要深度、要兩邊同時填到；競爭在加速。
中間價互補（0.55+0.42 類）做 taker 毫秒 低 Crypto taker 費喺 50¢ 附近最大；3¢ 缺口會變負。
GTC 兩邊掛單等 rebate 秒至分鐘 中 文中講得對：maker 0 費。風險係單邊成交變成裸倉。
CTF merge 回收資金 1–3 秒鏈上 高 官方支援 mergePositions。15 分鐘盤即使等到結算，資金凍結都短。
組合／關聯市場套利 秒至分鐘 中低 官方而家有 Combos RFQ，報價窗 400ms。搜尋空間大，工程重。
5 分鐘 BTC 方向預測 5 分鐘 低 作者自己用 ML 證明接近 50%。唔好做。
新聞搶先 / 已決事實 秒 中 邊緣喺資訊延遲，唔喺語言選擇。要合規數據源。
天氣梯級（香港氣溫） 小時至日 高（工程） 結算源係香港天文台 Daily Extract，唔係即時溫度 App。延遲牆幾乎無關。
熱路徑塞 LLM agent — 負價值 套利決策必須係確定性函數。LLM 只適合研究同審查，唔適合落單循環。

五、20ms 牆：方向對，數字唔係瓶頸

官方文件標明主撮合在 AWS eu-west-2，最近非限制區 eu-west-1，完成 KYC/KYB 可以申請同機房共置。獨立工程測算（Poly Syncer, 2026-05）同官方行為一致：

階段時間可唔可以靠換語言剷走
WebSocket 盤口更新間隔80–200 ms唔得。快過 feed 等於空轉。
撮合確認（獨立估計）10–30 ms唔得。呢個先係文中講嘅「牆」。
EIP-712 簽名10–40 ms部分可以。預熱密鑰池就夠。
提交閘道 RTT30–80 ms靠區域，唔靠 Rust。
零售端到端150–300 msPython 夠用。
頂級團隊端到端60–120 ms同區 + 長連線 + 本機盤口。
鏈上結算1.5–3 s唔阻擋下一筆決策。

所以「唔好為 0.5ms 改寫 Rust」呢句係對嘅。錯喺把 20ms 講成唯一約束。真正殺死毫秒級策略嘅係 80–200ms 嘅盤口心跳 + 提交 RTT。策略必須設計成幾秒窗口：尾盤、新聞後錯誤定價、掛單深度、關聯約束。

撮合重啟期間 API 會回 HTTP 425，之後兩分鐘只接受 postOnly。生產 bot 一定要處理，文中完全冇提。

六、費用：文中公式係錯嘅，但結論（盡量做 maker）係對嘅

官方公式：

fee = C × feeRate × p × (1 − p)
# Crypto feeRate = 0.07；Maker 永遠 0；rebate 約為 taker 費池 20%

費喺 50¢ 最大，兩極接近 0。所以「中間價 3 仙缺口、兩邊 taker」會虧；「0.97+0.01 尾盤」即使 taker 都可能仲有淨利。

七、正確架構：流水線，唔係「一隊 Grok」

文中把模組叫做 agent，再包裝成 Grok Build 故事。熱路徑如果真係等 LLM 回覆，套利已經冇咗。可建、可維護嘅形狀係確定性流水線：

1. 盤口CLOB WebSocket 維護本機 book；自己成交即時扣減，唔等下一幀 80–200ms。
2. 獵人用 ask+ask（你要付出嘅價）同深度，唔用 mid。輸出缺口 × 可成交量。
3. 閘門兩邊深度、庫存平衡、過平報價（可能係過期單）、費用曲線、單日虧損熔斷。
4. 執行預熱 HTTPS、EIP-712、盡量 post-only GTC；單邊成交即對沖或停機。配對後 merge。

LLM 只放喺盤後：解釋虧損、攻擊回測、檢查有冇未來函數。唔放落單循環。

九、法律、地理、唔好做嘅事

Polymarket 官方 geoblock 名單（2026-08 文件）冇列香港，API 技術上可下單。美國、英國、新加坡、德國、法國等係限制區。技術可達 ≠ 當地合法。

香港投資者及理財教育委員會（IFEC，證監會附屬）2026 年 4 月公開提醒：參與預測市場可能構成《賭博條例》下的非法賭博，合約唔係投資產品，亦不受《證券及期貨條例》保障。呢份研究唔構成法律意見，亦唔教人繞過 geoblock。

明確排除：

  • 內幕消息、跟「未公開事實」下注。
  • 用 VPN 偽裝受限司法管轄區。
  • 把私人金鑰寫進網頁或公開庫。
  • 抄單：鏈上見到嘅時候缺口已經冇咗，而且單邊 PnL 會誤導。

十、若要建，唯一合理路徑

  1. 紙盤掃描：ask+ask、深度、官方費用曲線。連續記錄幾日，睇真實可成交缺口分佈。
  2. 用錄製嘅 book 回測，假設單邊成交會發生。回測永遠雙腿成交＝作假。
  3. 零餘額 dry-run：對住真實拒絕原因（精度、allowance、425、深度消失）。
  4. 極小資金、單一 15 分鐘系列、硬止損、裸倉警報、崩潰後唔好重覆下單。
  5. 主機放 eu-west-1／eu-west-2。Python 先。熱路徑唔好 LLM。

本倉庫只提供第 1 步。唔提供帶私鑰嘅自動交易迴路。
